# CG-CLIP v0.1 实验报告：原生对齐 ＋ 文本门控的最后层 CLS 注意力对齐

**臂（arm）**：`CG_CLIP_V01`　**objective**：`clip_native_caption_gated_cls`　**phase**：`cgclip-v0.1`
**门控类型**：`caption_gated_final_cls_attention`
**实现提交**：`31affcbeff22bc6039a3d65d6cfab8f24d260373`（分支 `codex/cgclip-v01`，基线 `6887793`）
**训练**：4×A800-80GB，每卡 256 对（全局 1024 对），**恰好 500 次优化器更新**，无扫描、无补跑、无第二个配置
**结论一句话**：**门控确实学会了"关掉大部分 patch"（正样本对上平均保留 64.2/196），条件路径在自己的目标上也确实比原生路径拟合得更好（batch 内 I2T top1 0.9609 vs 0.9531），但把这份训练信号接回共享主干 500 步之后，原生读出在两份冻结评测上都掉到了下限以下 —— COCO I2T R@1 0.5952（下限 0.6058，差 1.06pp = 5000 个图像查询里的 53 个）、T2I R@1 0.40852（下限 0.41236，差 0.384pp = 25000 个文本查询里的 96 个），判定 FAIL。这是本项目目前为止在 COCO 上测得的最大一次负向变化，幅度大于同配置 run 间波动（0.02–0.30pp）。**

## 1. 这一臂到底做了什么

保留**全部**原生结构（12 层视觉 Transformer、`ln_pre`、`ln_post`、`visual.proj`、文本 Transformer 与 `text_projection` 一律不动），只在**最后一个视觉块**里让文本决定"CLS 该读哪些 patch"：

```
X11 = [CLS11, patch11_1 … patch11_196]        # 进入第 12 个视觉块的 token，由一次视觉前向（块 0..10）给出

原生:   a[h,p] = softmax_p( q_cls[h]·K[h,p] / √64 )
        oG = out_proj(⊕_h Σ_p a[h,p] V[h,p] )
        cG = c + oG + mlp(ln_2(c + oG));   vG = Norm(ln_post(cG) @ W)

条件:   qT_j = A(stop_grad(t_j))                 # 512→64，无 bias，零初始化
        kG_i,p = B(stop_grad(U_i,p))             # 768→64，无 bias，xavier
        p = sigmoid(qT_j·kG_i,p/√64 + b)         # b 是可训练标量，初始 log 8
        m = hard(p≥0.5) + (p − p.detach())       # 196 个 patch 门，直通估计
        m_full = [1, m]                          # CLS 槽固定 1
        a_cond = (a · m_full) / Σ_p (a · m_full) # 无 detach、无 clamp
        oA = out_proj(⊕_h Σ_p a_cond[h,p] V[h,p] )   # 同一个 out_proj
        cA = c + oA + mlp(ln_2(c + oA));   vA = Norm(ln_post(cA) @ W)   # 同一条尾部
```

两条路径共享**同一个** CLS Query、**同一套** Key/Value、**同一个** `out_proj`、残差、`ln_2`/MLP、`ln_post`、`visual.proj`。
目标函数固定：`L_total = 5·LG + 5·LA + 1·LS`，`LG`/`LA` 都是双向交叉熵，`LS` 只统计**真实正样本对**的 196 个 patch 门（不含 CLS 槽），相似度固定尺度 100。

**没有做**（规格里的禁止项，代码里也不存在相应开关）：文本 Query 替换 CLS Query；把文本向量/bias 加到视觉输出；第二套 Value 来源；复制最后一块或投影层；PG/SmartCLIP 式投影后通道掩码；文本掩码/U 重建/教师模型/第三条路径。

初始化时刻的精确事实（验收测试 A/B 组逐条验证）：`A=0` ⇒ `qT=0` ⇒ 196 个门**全开**、`a_cond ≡ a`、`QA ≡ QG`、`LS = 1`；`A` 与 `b` 的梯度非零，而 `B` 的梯度**恰好为 0**（第一步之后才恢复）。

## 3. 训练过程实测

**损失（step 500，rank0 本地批口径）**：`LG = 0.3054`（I2T 0.1320 + T2I 0.1734）、`LA = 0.2950`（I2T 0.1253 + T2I 0.1698）、`LS = 0.3274`，`L_total = 5·LG + 5·LA + 1·LS = 3.3297`。
两个有意思的细节：`LA < LG`（条件路径在自己的目标上拟合得略好），且 batch 内条件路径的 I2T top1（0.9609）与正样本获胜比例（0.961）都略高于原生路径（0.9531 / 0.953）。**但这只说明它在自己的 batch 目标上更好，不能说明原生表示更好** —— 冻结评测给出的结论相反（见 §4）。
`CE` 与 `softplus(−LSE margin)` 的最大绝对差在四个方向上都 ≤ 1.2e-6（自检字段 `ce_from_lse_margin_max_abs_diff`），说明日志里的 CE 与 LSE margin 是同一套定义下的两个量，没有被混用。

**门控演化（正样本对，196 个 patch 门；每 25 步一次重日志）**

| 200 | 74.8 | 0.3936 | 0.2584 | 0.1137 | 0.2381 | 0.0804 |

- 门**单调地越关越多**（100.6 → 56–64 之间波动），最终在正样本对上保留约 1/3 的 patch；
- 全程**没有出现全关或全开**（`all_off_fraction = all_on_fraction = 0.000`，每一步都如此），所以它不是退化成常数掩码；
- 有约 **11.8%** 的门概率落在 0.5±0.05 的近阈值带里 —— 直通硬门在这些坐标上会随噪声翻转，这个比例在报告"门稳定性"时必须一起读；
- **跨图像变化 0.2222 远大于跨文本变化 0.0945（约 2.4 倍）**：这个门学到的主要是"图像侧"的差异，文本侧的调制弱得多。也就是说，虽然机制上文本是唯一的条件输入，但 500 步后它更像一个图像内容选择器，而不是 caption 条件选择器。这是一条**机制层面**的观察，不是能力结论。

## 5. 实现期发现并修掉的真实 bug

这些是"实现→测试→真实入口验收"这条链上实际抓到的缺陷，全部有回归覆盖：

1. **`native_cls_row` 误用 `last.ln_post`**：Claude 式的重构里把传入的 `ln_post` 写成了模块属性，真实模型冒烟第一步就 AttributeError。
2. **门控 logits 的 einsum 维度错位**：`'jd,idp->ijp'` 与 `kG` 的实际布局不符（`[i,196,64]`），真实入口直接崩。
3. **门控 logits 的输出顺序写反（最严重的一条）**：`'jd,ipd->ijp'` 应为 `->jip`，导致掩码布局是 `[图像, 文本, patch]`，而下游（重归一化、正样本列切片、诊断）全部按 `[文本, 图像, patch]` 使用 —— 这是一次真正的 **pair 索引转置错误**。它只在"两 rank DDP 单步 vs 单进程参考"和"分块 vs 逐对循环"两类测试里暴露；只测 1×1 或对角线的用例会漏掉它。
4. **`attention_map_grid` 返回嵌套列表**：重日志（14×14 栅格）在第 2 步崩。这个是在 4 卡 4 步冒烟里抓到的，否则会在正式 run 的第 25 步崩。
5. **`gate_statistics` 的两个变化量标签写反**（跨图像/跨文本互换）。
6. **runner 侧的三个问题**：`verify` 阶段把 `precision` 强判为 dict（而检查点里它是描述性字符串）；`<STUDENT_EXPORT>` 占位符只在"整 token 相等"时替换，导致 `500:<STUDENT_EXPORT>` 原样传给了评测器；Urban 结果读取器假定了另一种 JSON 布局（实际是 `urban1k.image2text.R1`）。三处都修成"读真实文件、按真实现状容错"，没有加任何绕过开关。
7. **导出学生缺 `completed_steps`**：两份冻结评测器都会断言步数，导出工具原先只写 `{'model': ...}`，已按 PG 臂的约定写入步数并重跑了两份评测（下面 §8 记录了这次重跑对 provenance 的影响）。
8. **只读快照工具广播维写错**（`[12,197] × [197]`），已修。

## 6. 验收测试

`tests/test_cgclip.py` **21 项全部通过**（真实 ViT-B/16 与真实缓存权重，非 mock）：

- **A** 原生 CLS 行与**未经改动的原生块**、以及与 `encode_image` 端到端在数值与梯度上一致；12 头 ×64 维与文本 8 头不混淆。
- **B** 初始化全开：`a_cond ≡ a`、`QA ≡ QG`、`LS = 1`；`∇(5LG+5LA) = 10∇LG`；`A`/`b` 梯度非零而 `B` 恰好为零。
- **C** 分块（含激活检查点）与逐对循环在分值与梯度上一致；正样本门取自全局正样本列 `rank·B+i`，且不重复评估门控。
- **D** 重归一化**等于**独立的"掩码 logits + softmax"定义；四个具名错误变体（不重归一化的 Value 掩码、软概率代替直通硬门、pair 索引转置、文本 Query 替换 CLS Query）都被测出显著差异；逐对索引与固定尺度 100 单独验证。
- **E** 直通梯度满足经**独立实现**验证的链式法则 `Σ_p (∂score/∂m_p)·p_p(1−p_p)`，且与"分母 detach"变体可区分（这条测试特意**不用**有限差分：直通门的前向值是分段常数，有限差分不是合法判据）。
- **F** 196 门全关 ⇒ 退化为纯 CLS 自读、分母有限为正、分值有限；注意力出现非有限/非正值时**报错拒绝**而不是 clamp。
- **G** LSE margin 定义、`CE = softplus(−LSE margin)`、权重 5/5/1、稀疏项不含 CLS 槽、门初始化与 RNG 隔离。
- **H** 优化器分组覆盖每一个可训练参数恰好一次，最后一块与 `visual.proj` 唯一归属，`mask_net`/`logit_scale` 冻结。
- **I** 用**生产写检查点函数**做真实保存/恢复（非初始门 + 优化器状态 + 步数游标）；摘要可复算、篡改/缺失可检测、跨目标/跨门控恢复被拒绝。
- **J** CLI 面：训练参数默认值符合冻结配置；runner 没有 sweep/补跑/`allow-missing` 类开关。
- **K** 真实两 rank DDP 单步梯度**严格等于**两个 rank 归约前梯度的算术平均（并检查两者确实不同，避免空测试），且与单进程全批参考一致（9 个张量，余弦 > 0.9999）。

## 7. 不能宣称的（NOT RUN / 归因限制）

- **未跑**任何控制臂：native-only、native+post-projection、只训门控不训主干、把条件路径换成别的注意力掩码方式。因此本轮只能说"CG-CLIP 这一整套组合在 500 步内把原生 COCO 读出压到了下限以下"，**不能**单独归因到门控重归一化、稀疏项、或两条路径共享参数中的任何一项。
- **未做**两路融合或重排序评测（本轮也没有评估条件路径的检索能力；它在推理期根本不存在）。
- **未做**超参搜索、多 seed、更长训练、3 个 epoch 训完（余弦 horizon 3651，实际只走了 500）。单 seed、单配置 ⇒ 6.3pp 这类结论以外的**小差异**（0.02–0.30pp）不能当作真实效应。
- **未做**浏览器目视验收：只读前端区块做了端点与无头渲染校验，页面在你浏览器里的实际观感我没有确认。
- **未做**人工图像检查（哪些 patch 被关掉是否符合语义）。
- **未产出**本轮的门控快照之外的可视化材料（14×14 栅格在日志与只读快照里都有原始数值，但没有做论文级成图）。

### 8.1 步时横向对比（各臂自己日志里的 `sec_per_step`；同一台机器、同样 4 卡 DDP）

| 臂 | 步数 | 步时均值 | 后 40 步均值 | 单步最慢 |
| --- | --- | --- | --- | --- |
| S0 baseline（无门控、无辅助目标） | 500 | 1.00 s | 0.90 s | 10.21 s |
| S0 续训 500→1000 | 1000 | 0.93 s | 0.92 s | 1.18 s |
| **PG-CLIP v0.1**（投影前 768 维条件掩码，分块 8×32） | 500 | 1.27 s | 1.05–1.09 s | 13.01 s |
| **CG-CLIP v0.1**（本臂，分块 32×64） | 500 | **2.21 s** | **2.04 s** | 12.03 s |

结论很清楚：本臂一步约等于 **1.74×** PG 臂、**2.2×** 原生基线。代价来自结构本身 —— 条件路径要为**每一对（文本, 图像）**重跑最后一块的 CLS 核心（`out_proj` + 两个 MLP + `ln_post` + 投影），而 PG 臂只在投影前乘一次 768 维掩码；再加上规格要求的**显式 fp32 且关闭 TF32**（拿不到张量核加速）与非重入激活检查点（反向重算，约 +33% FLOPs）。分块对这个代价极其敏感：同一份代码在 `8×32` 下是 6.3 s/step、`32×64` 下是 2.0 s/step（显存同为 40.7 GiB），所以正式 run 前先量后调、采用后者。
